# tasks-api

[![CI](https://github.com/joalberto902/tasks-api/actions/workflows/ci.yml/badge.svg)](https://github.com/joalberto902/tasks-api/actions/workflows/ci.yml)

A RESTful task management API written in Go, backed by PostgreSQL and packaged with Docker. It uses only the standard library for HTTP routing and `pgx` for database access.

## Features

- Full CRUD for tasks (create, list, get, partial update, delete)
- PostgreSQL persistence with parameterized queries and SQL migrations
- Repository pattern: handlers depend on an interface, with PostgreSQL and in-memory implementations
- Input validation and consistent JSON error responses
- Request body size limit (`413 Payload Too Large`)
- Structured logging with `log/slog`
- Graceful shutdown on `SIGINT` / `SIGTERM`
- Configuration through environment variables (12-factor)
- Multi-stage Docker image running as a non-root user
- Docker Compose setup for the API and the database
- Unit and integration tests, run on every push with GitHub Actions against a real PostgreSQL instance

## Tech stack

| Area | Technology |
| --- | --- |
| Language | Go |
| HTTP | `net/http` (`ServeMux` with method and path patterns) |
| Database | PostgreSQL 16, `pgx` v5 (`pgxpool`) |
| Containers | Docker, Docker Compose |
| CI | GitHub Actions |

## Getting started

### Prerequisites

- [Docker](https://docs.docker.com/get-docker/) with the Compose plugin
- Go (version in `go.mod`) — only needed to run the tests locally

### Run with Docker Compose

```bash
git clone https://github.com/joalberto902/tasks-api.git
cd tasks-api
docker compose up --build
```

The API will be available at `http://localhost:8080`.

```bash
curl http://localhost:8080/health
# {"status":"ok"}
```

To stop the stack:

```bash
docker compose down        # keeps the database volume
docker compose down -v     # also removes the database volume
```

### Configuration

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `DATABASE_URL` | yes | — | PostgreSQL connection string |
| `PORT` | no | `8080` | Port the HTTP server listens on |

## API

Base URL: `http://localhost:8080`

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/health` | Health check |
| `GET` | `/tasks` | List all tasks |
| `POST` | `/tasks` | Create a task |
| `GET` | `/tasks/{id}` | Get a task by ID |
| `PATCH` | `/tasks/{id}` | Partially update a task |
| `DELETE` | `/tasks/{id}` | Delete a task |

### Task

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Generated by the server (UUIDv7) |
| `title` | string | Required, must not be blank |
| `status` | string | `todo` (default), `ongoing` or `done` |
| `description` | string | Optional |
| `created_at` / `updated_at` | timestamp | Set by the server (UTC) |

### Examples

Create a task:

```bash
curl -i -X POST http://localhost:8080/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "Write the README", "description": "Document the project"}'
```

List tasks:

```bash
curl http://localhost:8080/tasks
```

Update only the status (fields omitted from the body are left unchanged):

```bash
curl -X PATCH http://localhost:8080/tasks/<id> \
  -H "Content-Type: application/json" \
  -d '{"status": "done"}'
```

Delete a task:

```bash
curl -i -X DELETE http://localhost:8080/tasks/<id>
```

### Errors

Errors are returned as JSON in the form `{"error": "message"}`.

| Status | When |
| --- | --- |
| `400 Bad Request` | Invalid JSON, invalid ID, or invalid `title` / `status` |
| `404 Not Found` | The task does not exist |
| `413 Request Entity Too Large` | Request body larger than 1 MiB |
| `500 Internal Server Error` | Unexpected failure (details are logged, never returned) |

## Development

Run the unit tests:

```bash
go test -race ./...
```

The PostgreSQL integration tests are skipped unless `DATABASE_URL` is set. To run them against a local database with the migration applied:

```bash
export DATABASE_URL="postgres://postgres:dev@localhost:5432/tasks"
go test -count=1 -v -race ./...
```

Build the binary:

```bash
make build
```

### Continuous integration

On every push, GitHub Actions runs `go vet`, `go build` and the full test suite (including the integration tests) against a PostgreSQL service container after applying the migration.
